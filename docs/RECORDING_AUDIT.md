# Исправление записи поездок на iPhone

Дизайн, HTML-разметка и CSS сохранены. Изменены сбор данных, разрешения,
сохранение, синхронизация и отображение доступности рассчитанных показателей.

## Причины исходного поведения

1. `devicemotion` отбрасывался целиком при GPS старше пяти секунд либо без
   координат. GPS с точностью хуже 35 м сбрасывал признак актуальности. Поэтому
   реальные события акселерометра могли вообще не попадать в запись.
2. Завершение поездки при менее чем 50 событиях прерывало сохранение. Не
   сохранялись даже реальные GPS, длительность и имеющиеся данные движения.
3. Запрашивалась начальная позиция через `getCurrentPosition`, после неё
   запускался отдельный `watchPosition`. Разрешение движения также запрашивалось
   при каждом старте страницы, даже если уже было выдано в этом документе.
4. Черновики с менее чем 50 событиями не восстанавливались. Ошибка локального
   сохранения закрывала экран записи без возможности повторить её завершение.
5. Пропуск данных браузером в фоне приводил к серверному отказу из-за разрыва
   временного ряда. Денежная оценка на клиенте при этом строилась по отдельной
   условной формуле и не совпадала с подтверждённым расчётом сервера.

## Текущее поведение

GPS и IMU записываются независимо. Сохраняются исходные временные метки,
точность GPS, отсутствующие значения осей, интервалы событий и состояние
разрешений. Для каждой поездки используется один `watchPosition`; после
завершения он отключается. Разрешение движения запрашивается непосредственно
при нажатии кнопки iOS и повторно не запрашивается после ответа в том же
документе. Отказ в IMU не мешает записывать GPS.

Запись сначала помещается в IndexedDB, затем отправляется на сервер. Сеть
ограничена тайм-аутом; ошибка сети/валидации не удаляет данные. После успешного
подтверждения очередь очищается. Запись с недостаточной точностью GPS, без IMU,
без GPS, с разрывами либо вообще без показаний всё равно появляется в истории
с длительностью и характеристиками качества. Расчётные показатели недоступны,
когда для них недостаточно достоверных данных; экономия не начисляется,
неизвестные показатели не показываются как измеренные нули.
Отклонённая старая запись остаётся в очереди для восстановления, но ответ
400/409/413/422 по ней не блокирует отправку остальных поездок. Ошибки
авторизации, ограничения частоты и сбой сервера останавливают текущую попытку.

Для полного расчёта нужны не менее 50 согласованных IMU-точек, достаточное
покрытие поездки GPS/IMU и непрерывный ряд. Прежний расчётный конвейер сохранён
для подходящих данных. Старые запросы без `raw_recording` сохраняют прежние
правила и формат хеша, чтобы повтор старой отправки оставался идемпотентным.

Сырые данные и запись истории сохраняются в одной транзакции в уже имеющиеся
таблицы. Повторная отправка не увеличивает счётчики. Экспорт доступен владельцу
по `GET /api/v2/trips/<session_id>/export`. Идентификатор берётся из ответа
`/api/v1/telemetry/session`. Новые столбцы и пересоздание базы не требуются.

## Разрешения iPhone и ограничения браузера

Веб-сайт не может навсегда выдать себе разрешение iOS. Если выбрано «Разрешить
один раз», следующая поездка может вызвать новый системный запрос. Для Safari
проверьте разрешение геопозиции именно для `https://autoxak.ru`: меню страницы
→ настройки веб-сайта → геопозиция → разрешить. В настройках iOS проверьте
«Конфиденциальность и безопасность → Службы геолокации → Веб-сайты Safari».
Для Chrome разрешение iOS настраивается отдельно для этого приложения.
Для сохранения разрешений используйте обычную вкладку и включённую «Точную
геопозицию» в настройках iOS. Приватный режим и разрешение «Один раз» могут
потребовать нового подтверждения.
`www.autoxak.ru`, IP-адрес и `autoxak.ru` — разные источники разрешений и
хранилищ: используйте один адрес `https://autoxak.ru`.

Вращение неподвижного телефона не является поездкой автомобиля и не должно
создавать километры, экономию или дорожные события. Полученные сигналы всё
равно сохраняются; в итоге указано количество GPS/IMU-точек. Денежный результат
показывается после ответа расчётного сервера, а не выдумывается при движении
телефона. Держатель телефона и фактическое движение автомобиля нужны для
осмысленных показателей стиля вождения.

iOS может приостанавливать браузер при блокировке экрана и уходе в фон.
Приложение запрашивает Wake Lock, сохраняет черновик каждые пять секунд,
при скрытии страницы и при выходе. После возвращения Wake Lock запрашивается
снова. Фоновая работа PWA не гарантируется ОС; для проверки держите страницу
открытой и экран включённым. Пропуски сохраняются как реальные пропуски,
не заполняются вымышленными событиями.

## Проверки

Серверные сценарии проверяют сохранение GPS без IMU, IMU без GPS, пустую
запись, повторную конкурентную отправку, историю/экспорт, полный расчёт,
пропуски в фоне, недопустимые метки времени и откат при ошибке расчёта.
Браузерные сценарии в Chromium моделируют iOS `requestPermission` с проверкой
жеста пользователя, слабый GPS, отказ разрешения, повторный старт, офлайн,
повтор после ошибки IndexedDB и восстановление прерванной записи.
Активная запись защищена Web Lock: другая вкладка не должна отправлять её
черновик как уже прерванную поездку. После окончания или закрытия страницы
блокировка снимается. Короткие дистанции выводятся в метрах, чтобы реальные
10–20 метров не округлялись до «0 км».
Это не заменяет приёмку на физическом iPhone и реальную дорожную калибровку
WearEngine: его точность по парным смартфон/OBD-логам пока не подтверждена.

## Применение к существующему серверу

```bash
cd /opt/autoxak-production &&
git pull --ff-only origin feat/production-deployment &&
bash deploy/production.sh update
```

`update` создаёт дамп перед заменой API, получает изменения текущей отслеживаемой
ветки, собирает новый образ и проверяет готовность контейнера. Секреты, том
PostgreSQL и конфигурация Nginx сохраняются. Повторный запуск миграции либо
ротации ключей для этого исправления не нужен. После обновления перезагрузите
страницу на iPhone и проверьте короткую запись: начало, 10–20 секунд, завершение,
наличие в истории. Смотрите количество полученных GPS/IMU-точек в сообщении
о неполных данных; нулевые значения показывают, какое разрешение проверить.
