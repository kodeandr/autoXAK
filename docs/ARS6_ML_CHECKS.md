## Что добавлено

- Отдельная задача `ML containers and browser` в `.github/workflows/test.yml`.
  На push/pull_request она собирает runtime/controller, устанавливает Chromium,
  включает `AUTOXAK_ML_DOCKER_INTEGRATION=1`, выполняет `tests/ml`, оба браузерных
  сценария и диагностические тесты. Этот job не обращается к production и не развёртывает код.
  Обязательность проверки для слияния настраивается владельцем в правилах ветки отдельно.
- Контейнерные сценарии проверяют применённые Docker ограничения, отсутствие сети,
  секрета приложения и Docker socket у кандидата, неизменяемый image ID, успешный
  прогноз, Python-ошибку, отрицательный расход, таймаут, превышение памяти и размера ответа.
- Браузерный сценарий загружает ZIP, выполняет реальный расчёт, проверяет метрики и
  видимую ошибку Python. Затем останавливает контроллер, ставит две синтетические
  задачи в очередь в пределах окна heartbeat, перезапускает API и контроллер,
  проверяет неизменность сохранённых результатов и снимков, порядок выполнения очереди
  и отображение результатов после обновления страницы.
- Исправлена передача timeout в `page.waitForFunction`; браузер по умолчанию берётся
  из установленной версии Playwright. `CHROMIUM_PATH` остаётся доступным переопределением.
- `test_ml.sh check` теперь требует готовности API и вычислителя. Отдельный `smoke`
  загружает контролируемый синтетический пример и проверяет результат. Без `--run-synthetic`
  скрипт `scripts/ml_smoke.py` выполняет только чтение.

## Воспроизведение на Linux

Нужны Docker Engine API 1.45+, Python 3.12 и Node.js. Не запускайте недоверенные
модели на рабочем сервере через эти тесты: используются только фиксированные тестовые сценарии.

```bash
python -m pip install -r requirements.txt
npm ci --prefix tests/browser
(cd tests/browser && npx playwright install --with-deps chromium)
docker build -f deploy/Dockerfile.ml-runtime -t autoxak-ml-runtime:qa .
docker build -f deploy/Dockerfile.ml-controller -t autoxak-ml-controller:qa .
python -m unittest discover -s tests/diagnostics -v
AUTOXAK_ML_DOCKER_INTEGRATION=1 python -m pytest --confcutdir=tests/ml tests/ml -ra
PYTHON_BIN=python node tests/browser/ml.cjs
PYTHON_BIN=python node tests/browser/ml_workbench.cjs
```

Браузерный сценарий использует настоящий ML API router с отдельным хранилищем,
настоящие controller/runtime-контейнеры и Chromium. `/ready` в этом маленьком
тестовом приложении — фикстура доступности HTTP, а не проверка PostgreSQL/Redis.
Регрессии полного приложения остаются в существующем job `test`; на развёрнутом
стенде `test_ml.sh check` обращается к настоящему `/ready` приложения.

Артефакты job: JUnit (`pytest.xml`), IDs собранных образов, `report.json`, снимки
страницы до/после перезапуска и ограниченные логи. Все поездки в них синтетические.
Результат `succeeded` не сертифицирует точность обученной модели.

## Что действительно проверено локально

- 16 диагностических unittest пройдены (7 ARS-5 и 9 ARS-6).
- Синтаксис изменённых Python, обоих JavaScript сценариев и Bash проверен.
- `git diff --check` пройден.
- HTTP-проверка публичного стенда из локального Python не завершилась:
  первоначально не удалось получить `/ready`; при повторе `/ready` ответил,
  но запрос `/api/v3/ml/runs` завершился сетевой ошибкой/таймаутом. Это не
  подтверждает ни готовность, ни неисправность модели на сервере.

Полные `tests/ml` требуют Linux (`fcntl`), а контейнерные сценарии — Docker.
В текущем Windows-окружении Docker отсутствует, поэтому эти тесты и браузерный
сценарий **не выполнялись**. Заглушка `fcntl` или mock-контейнеры не использовались.

Подключённый GitHub сообщил `pull=true`, `push=false` для `kodeandr/autoXAK`,
но у аккаунта уже есть форк `sovestinet1/autoXAK` с `push=true`.
Публикация возможна через отдельную ветку форка и PR в `feat/public-test-model-manager`.
Прямой Write в репозиторий разработчика для этого не нужен. GitHub может потребовать
одобрения запуска workflow от владельца исходного репозитория.
Фактический статус прогона следует проверять в Checks PR; подготовка workflow
сама по себе не подтверждает прохождение проверок.
