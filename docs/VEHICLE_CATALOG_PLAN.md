# Расширение каталога autoXAK: Россия, подержанные автомобили и импорт

Дата проверки: 27 октября 2026 года. Основа кода: `main`, коммит `9969ec0`.
Рынок — Россия, включая подержанные автомобили и параллельный импорт, согласно
последнему ответу владельца. Модель данных должна позволять добавить рынки СНГ.

## Решение

Нужны одновременно расширение покрытия и изменение структуры справочника.
Рекомендация: локальный каталог в PostgreSQL, лицензированная выгрузка
модификаций для основного наполнения, документы производителей для проверки
технических полей. Бесплатный справочник марок/моделей пригоден как основа
навигации после уточнения условий использования, но не заменяет модификации.

Материалы этого изменения — анализ и план. Рабочий код, дизайн, seed и серверная
БД не менялись. Чужие выгрузки не включены в репозиторий и не импортированы.

## 1. Что действительно есть в проекте

В `seed_fleet.py` — **5 марок, 5 моделей и 9 модификаций**:

| Марка | Модель в seed | Модификации |
| --- | --- | ---: |
| Haval | Jolion | 2 |
| Skoda | Octavia | 3 |
| Geely | Coolray | 1 |
| LADA | Vesta NG | 2 |
| Chery | Tiggo 7 Pro Max | 1 |

Это подсчёт штатной выгрузки в репозитории, а не результат запроса боевой БД.
Из облачной среды публичный каталог `autoxak.ru` недоступен: HTTPS CONNECT
отклонён прокси среды с 403. Это не свидетельство сбоя сайта. Проверять число
записей на сервере нужно SQL-командами из раздела 10.

Обнаруженные ограничения:

1. **Нет поколений, рестайлинга, годов действия, рынка и кода двигателя.**
   Название «Octavia 1.4 TSI DSG» не задаёт однозначную машину. В seed Vesta
   подписана NG, но отдельной сущности поколения нет.
2. **Три разных каталога.** PostgreSQL, резервный каталог API (3 записи) и
   `FALLBACK_CATALOG` в `static/setup.html` (14 вариантов, 8 моделей, 6 марок).
   Audi Q3 есть в резервном каталоге браузера, но отсутствует в seed.
   Часть ID расходится: например, `geely_coolray_15t` в браузере и
   `geely_coolray_15t_fwd` в seed. Массы для одинаковых ID также расходятся.
3. **Неизвестные поля нельзя сохранить честно.** В `VehicleTrim` обязательны
   масса, CdA, объём/мощность двигателя, объём/вязкость/допуск масла.
   Качение, КПД, марка масла и сервисные часы имеют значения по умолчанию.
   Во всех 9 seed-вариантах выставлено 250 сервисных часов без указания источника.
4. **Нет происхождения значений.** Не указаны источник каждого параметра,
   документ/страница, версия выгрузки, рынок и дата проверки.
5. **Неполные модели невидимы.** API использует INNER JOIN с модификациями:
   импортировать только марки/модели и ожидать их появления в списках нельзя.
6. **Неподтверждённые числа ещё есть в выборе автомобиля.**
   `normalizeCatalogData()` подставляет расход 8,2 л/100 км и массу 1500 кг.
   `saveRegistryVehicle()` может сохранить такой расход в профиль.
   Это осталось в каталожной части после переработки математического ядра.
7. **Повторный seed перезаписывает поля существующих модификаций.**
   Старый `seed_fleet.py` нельзя использовать как механизм обновления проверенного
   большого каталога: он может затереть уточнённые параметры.
8. `print_catalog.py` ожидает старый иерархический ответ, хотя API возвращает
   `{catalog: [...], total: ...}`. Для аудита нынешнего каталога он непригоден.
9. API каталога не передаёт часть уже хранящихся полей: объём/мощность двигателя,
   тип коробки и привод. Клиент не может использовать их для различения вариантов.

**Вывод:** простое увеличение массива seed размножит неоднозначные записи и
неподтверждённые параметры. Перед массовым импортом нужно устранить эти ограничения.

### Дополнительные источники для согласования

- **Официальные технические документы и руководства производителей:** коды
  двигателей, мощность/единицы, варианты коробок и приводов, допуски/объём масла.
  Проверять конкретные рынок, год и исполнение. Общая страница модели недостаточна.
- **ОТТС/СБКТС и документы конкретной машины:** идентификация двигателя,
  мощности, исполнения и рынка. Доступность/условия получения требуют отдельной
  проверки; такие документы не заменяют руководство по обслуживанию.
- **TecAlliance/TecDoc:** кандидат на договорный источник идентификаторов и
  технической применимости. До выбора проверить покрытие новых китайских машин,
  разрешённое использование и нужные поля. Не считать его готовой картой двигателя.
- **[NHTSA vPIC](https://vpic.nhtsa.dot.gov/api/):** идентификация/VIN для
  американского рынка; не универсальный реестр российских/европейских модификаций,
  не источник CdA, Crr или масляных допусков. VIN не нужен для первого расширения.
- **[АВТОСТАТ](https://www.autostat.ru/):** данные состава парка для корректировки
  приоритетов. Нужна подходящая выгрузка с датой и условиями использования.
  Продажи новых машин не равны распространённости всего эксплуатируемого парка.

Эти дополнительные продукты и сайты здесь не исследованы до уровня договора
или контрольного набора. Auto.ru/Drom можно использовать для согласованной
сверки идентичности; массовое копирование их каталога не предлагается как
автоматически разрешённый способ наполнения.

## 4. Какую структуру хранить

Рекомендуемая идентичность технического варианта:

    Марка → Модель → Поколение/рестайлинг → Кузов/рынок/годы
        → Двигатель + коробка + привод + силовая установка

Комплектация оснащения хранится отдельно, если она не меняет технические поля.
Не превращать автоматически каждую Luxury/Elite/Comfort в другую физическую модель.

Минимальные данные:

| Блок | Обязательная информация для точного сопоставления |
| --- | --- |
| Идентичность | Собственный неизменяемый ID, внешний ID и источник, марка/модель, aliases |
| Применимость | Поколение/рестайлинг, кузов, начало/конец применимости, рынок, модельный год отдельно от календарного |
| Двигатель | Код/семейство при наличии, точный объём в см³, топливо, мощность и стандарт единиц |
| Трансмиссия | Тип, код/ступени при наличии, привод |
| Электрификация | ICE/MHEV/HEV/PHEV/EREV/BEV; параметры батареи и моторов только по источнику |
| Происхождение | Источник каждого значения, документ/страница, версия, дата, единицы, область применимости и статус проверки |

При неполной идентификации сохранять выбранную модель и уровень определённости;
код двигателя или год не выдумывать. Такой выбор не считается точной модификацией.

Необходимые дополнительные сущности: поколения/исполнения, источники и версии
выгрузок, `source_mappings` для внешних ID, происхождение параметров и конфликты.
Статус должен различать «неизвестно», «сообщено пользователем», «заявлено
поставщиком», «проверено по OEM», «измерено/калибровано» и «неприменимо».
Один общий `verified=true` на автомобиль не доказывает достоверность всех полей.

Параметры масла могут иметь несколько OEM-разрешённых вариантов по условиям;
нельзя свести их к универсальному сорту и рекламной марке. Объём замены с
фильтром и без фильтра — разные величины. Для BEV масло ДВС неприменимо.

### Особые случаи сопоставления

- LADA / ВАЗ / Lada (ВАЗ), Škoda / Skoda: нормализовать написание и хранить aliases.
- Solaris как марка и Hyundai Solaris как модель — разные сущности.
- Geely Coolray и BELGEE X50 не объединять автоматически.
- Chevrolet Niva и LADA Niva Travel: учитывать историю, годы и собственные ID.
- Fit/Jazz, Yaris/Vitz: сопоставление по рынкам, а не безусловное равенство.
- HEV/PHEV/EREV/BEV и версии китайского внутреннего рынка отделять от внешне
  похожих экспортных автомобилей. Не суммировать паспортные мощности разных
  моторов без определения системной мощности производителя.

## 5. Каталог и математическая модель

Должны быть разделены:

1. **Идентификация автомобиля:** возможность найти и сохранить свою машину.
2. **Паспортные сведения:** параметры с источником и областью применимости.
3. **Калибровочные данные:** необходимые конкретному расчёту наблюдения/карты.

Отсутствие CdA или карты двигателя не должно исключать машину из каталога и
блокировать запись поездки. Оно ограничивает доступность соответствующего расчёта.

Из открытого перечня моделей нельзя получить Crr, CdA, КПД трансмиссии, массу
конкретной загруженной машины, карту расхода RPM×torque или модель старения масла.
Даже подтверждённая снаряженная масса не равна массе в конкретной поездке.
Расход WLTP/NEDC/EPA, расход БК и измеренный поток топлива — разные наблюдения;
хранить цикл/условия, не подменять одно другим.

В существующей таблице потребуется миграция: разрешить NULL для неизвестных
технических полей, убрать автоматические физические/масляные значения,
пометить прежние seed-значения как legacy_unverified. `create_all()` не меняет
nullable/default уже существующих колонок — одного изменения ORM недостаточно.

## 6. Как заполнить и обновлять

    Выгрузка поставщика / OEM
        → приватный неизменяемый снимок + лицензия + SHA-256
        → промежуточная область импорта
        → проверка схемы, единиц, применимости и связей
        → сопоставление источников с собственными ID
        → отчёт dry-run: новые/изменённые/конфликтные/невалидные
        → ручной разбор конфликтов
        → транзакционный импорт проверенных записей
        → новая ревизия локального каталога и инвалидация кэша

Не исполнять полученный SQL-дамп поставщика от администратора рабочей БД.
Предпочтительнее CSV/JSON и собственный валидатор/импортёр.

Критерии импорта:

- Известные единицы; десятичные разделители и PS/mechanical hp/kW нормализованы.
- Только реальные сочетания агрегатов, допустимые годы, ссылки без сирот.
- Собственные ID стабильны; external ID уникален в пределах источника и типа.
- Изменения источника не переименовывают пользовательские `car_id` и старые поездки.
- Прежние записи деактивируются, но не удаляются каскадно. Снимки поездок не меняются.
- Импорт повторяем и идемпотентен; повтор не плодит варианты и не затирает OEM
  сведениями более низкого качества. Конфликтующие источники сохраняются раздельно.
- Новые неизвестные параметры остаются NULL. Для удаления значения требуется
  явное действие источника/ревью, а не случайный пропуск CSV-столбца.
- Перед применением — backup и пробный импорт на staging с возможностью отката.
  Частота обновления определяется периодичностью источника; локальный график
  проверки не выдаётся за гарантию появления всех новых моделей.

## 7. Интерфейс и сервер

Сохранить существующие три списка и дизайн:

    Марка → Модель (поколение, годы) → Модификация (двигатель, коробка, привод)

Уточняющие сведения помещаются в подписи вариантов. Это позволяет различать
машины без добавления новых экранов. Модель без модификации должна сохраняться
как неполная идентификация, а не через фиктивную «базовую 1.5 AT».

Каталог должен приходить из одного локального источника с ревизией. Вместо
разных резервных массивов — последняя известная локальная версия с явным
статусом. Удалить подстановки расхода/массы и восстановление выбора через
чужой Haval ID. Сохранённая машина не должна меняться при ошибке загрузки.

При росте числа вариантов — запросы по выбранной марке/модели/поколению,
индексы по связям и рынку/годам, ограниченные ответы и кэш по ревизии. Избежать
выдачи всей базы технических характеристик и построения тысяч DOM-элементов
на телефоне. Названия из источника вставлять через `textContent`, не как HTML.
Внешний поставщик не должен вызываться браузером при каждом выборе автомобиля.

Для текущего сервера с 2 ГБ RAM сначала измерить размер импорта, задержки SQL,
размер JSON и расход памяти телефона. Оснований покупать дополнительный сервер
лишь из-за количества марок сейчас нет; нагрузочный тест перед запуском обязателен.

## 8. Какой способ выбрать

| Вариант | Результат | Ограничение |
| --- | --- | --- |
| Только бесплатный список | Быстро добавить названия марок/моделей после уточнения прав | Не решает точные модификации и масло; потребуется ручное дополнение |
| Лицензированная база модификаций + OEM-проверка | Основной рекомендуемый путь | Нужны пробная выгрузка, цена, договор и проверка качества |
| Полностью ручное наполнение | Подходит для первых 20–50 контрольных модификаций | Долго поддерживать масштабный парк; нужны источники и ревью |
| Полностью автоматическое получение из объявлений/LLM | Не выбрано для продакшена | Не устанавливает достоверность модификаций, полноту, происхождение и права |

LLM можно использовать как помощника извлечения полей с указанием документа,
но не как автора характеристик, мощностей, масел и реально существующих сочетаний.
Точные цены поставщиков и трудозатраты здесь не оценивались по неподтверждённым
прайсам. Размеры таблиц и количество модификаций полного продукта неизвестны.

### Запрос на демо поставщику

Предоставить 50 точных технических вариантов из P0/P1, включая Audi Q3, несколько
поколений Octavia, разные Coolray, Vesta и китайские марки. Запросить поля
поколения/годов/рынка/кода двигателя/коробки/привода, источники, формат обновлений,
стабильность ID, объём RU и импортного покрытия, образец договора и цену.
Отдельно уточнить хранение на своём сервере, резервные копии, показ в приложении,
производные данные, атрибуцию и судьбу уже загруженных данных после окончания
подписки. Попросить показать, какие поля действительно доступны, а не обещать
карту двигателя или масло по одному общему названию.

Это готовый перечень требований, а не отправленное кому-либо сообщение.

## 9. Очерёдность работ и критерии готовности

1. **Основание:** снять фактический состав боевой БД; собрать обезличенные
   запросы «машины нет» и неоднозначные выборы; получить демо/условия источника.
2. **Структура:** поколения, рынки и источники; nullable-поля и миграции;
   убрать каталожные подстановки, сохранить прежние ID и внешний вид.
3. **Пилот:** проверить P0 и первые 20–50 технических вариантов. Сверить
   совпадения по документам, протестировать повтор импорта и восстановление.
4. **Покрытие:** P1, затем P2; переносить модели из P3 по реальному спросу.
5. **Поддержка:** ревизии, конфликты, обновления, измерение покрытия и очереди.

Реальные метрики:

- доля запросов пользователей, для которых найдена модель;
- доля полных запросов (есть год/двигатель/коробка), где найден точный вариант;
- доля неоднозначных результатов и незаполненных полей по каждому источнику;
- доля опубликованных значений с установленным происхождением;
- ошибки/конфликты и время обработки обновления;
- задержки API и работа списков на реальном телефоне.

Считать по уникальным запросам за объявленный период; запрос с неполными
данными не засчитывать как подтверждённое точное совпадение. Пока таких данных
и статистики парка нет, заявления «охватили 90% рынка» не обоснованы.

## 10. Как проверить именно серверную БД без изменений

На HOSTKEY эти команды только читают счётчики; пароли и строки подключения
в вывод не попадают. Пришедшие из репозитория seed/fallback не считаются
фактическим числом записей PostgreSQL.

```bash
cd /opt/autoxak-production

docker compose --env-file .env.production -f compose.production.yml exec -T postgres \
  psql -X -U autoXAK_user -d autoXAK_db -v ON_ERROR_STOP=1 <<'SQL'
BEGIN READ ONLY;
SELECT
  (SELECT count(*) FROM vehicle_makes) AS makes,
  (SELECT count(*) FROM vehicle_models) AS models,
  (SELECT count(*) FROM vehicle_trims) AS variants;
SELECT mk.name AS make, count(DISTINCT md.id) AS models, count(tr.id) AS variants
FROM vehicle_makes mk
LEFT JOIN vehicle_models md ON md.make_id = mk.id
LEFT JOIN vehicle_trims tr ON tr.model_id = md.id
GROUP BY mk.id, mk.name ORDER BY mk.name;
SELECT count(*) AS models_without_variants
FROM vehicle_models md
WHERE NOT EXISTS (SELECT 1 FROM vehicle_trims tr WHERE tr.model_id = md.id);
COMMIT;
SQL
```

После получения реальных счётчиков и демо источника можно оценить объём
миграции и выбрать поставщика. В этом изменении массовое наполнение и
изменение боевых таблиц не выполнялись.
