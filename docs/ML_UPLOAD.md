# Загрузка моделей через test.autoxak.ru

Страница `https://test.autoxak.ru/ml` и API `/api/v3/ml/models` доступны
без аккаунта, пароля и выдачи персональных прав, если одновременно заданы
`APP_ENV=test` и `ML_UPLOAD_ENABLED=true`. Любой посетитель может загрузить,
применить и удалить неактивную модель. Название и описание — подписи,
не подтверждение авторства. В production эти переменные не добавляются.

## Что загружать

Выберите одним действием четыре файла, суммарно до 20 МиБ:

- `catboost_direct.cbm`;
- `catboost_residual.cbm`;
- `model_card.json`;
- `provenance.json`.

Комплект совместим с существующим fuel-window-v1: 17 входов прямого CatBoost,
18 для остаточной модели (добавлен physics). Карточка содержит прежние
road_constants, два физических коэффициента, диапазоны обучения всех входов.
В provenance нужны model_version, selected_model (hybrid/catboost/physics)
и artifact_sha256 ровно для двух CBM и model_card.json. Для JSON при подсчёте
хеша CRLF нормализуется в LF, как в исходном загрузчике. Изменение признаков
или алгоритма их подготовки требует новой версии кода приложения.

На странице задайте название, описание, выберите файлы и нажмите «Загрузить
и проверить». Контрольные суммы и структура проверяются до загрузки CBM.
Ограниченный дочерний процесс проверяет CBM и три пробных входа. Он получает
только путь к временному комплекту, без секретов приложения. Лимиты:
30 секунд, 15 секунд CPU, 1 ГиБ виртуальной памяти, один поток вычислений.
Это ограничение адресного пространства, не резервирование RAM. Процесс
остаётся внутри общего лимита API-контейнера; на VPS 2 ГБ большие модели
и нагрузочные испытания требуют отдельного сервера.

Всего допускается 10 загруженных версий, 100 МиБ файлов. Загрузки
обрабатываются последовательно. Ошибочная загрузка очищается и не меняет
активную версию. Обучение, Python-код, pickle и ZIP не принимаются.

## Применение и удаление

После проверки нажмите «Применить». Версия переключается атомарно и
сохраняется в реестре на диске. Новые расчёты используют её, начатые расчёты
удерживают уже загруженный комплект. При ошибке переключения сохраняется
прежняя версия. Кэш хранит неизменяемые комплекты по пути, а не mutable current.

Для удаления активной версии сначала примените другую либо нажмите
«Вернуться к встроенной». Встроенный комплект не удаляется. Прошлые результаты
поездок не переписываются. При успешном прогнозе сохраняются model_version,
model_bundle_id, artifact_bundle_sha256 и feature_schema_version. ML остаётся
исследовательской оценкой топлива; денежные начисления и модель масла
не меняются. Ошибка ML возвращает model_unavailable, а не нулевой расход.

## Обновление существующей тестовой среды

Эта инструкция предназначена для уже созданных `/opt/autoxak-test/.env.test`
и `compose.test.yml`, проекта `autoxak-test`, порта 8001 и его существующей БД.
Не запускайте второй staging-стек: он использует ту же подсеть 172.29.251.0/24.

На сервере клонируйте ветку с функцией в отдельный каталог:

```bash
git clone --branch feat/public-test-model-manager https://github.com/kodeandr/autoXAK.git /opt/autoxak-ml-source
bash /opt/autoxak-ml-source/deploy/test_ml.sh start
bash /opt/autoxak-ml-source/deploy/test_ml.sh check
```

Скрипт собирает отдельный образ autoxak-test-api, сохраняет проверяемый дамп
тестовой БД, затем пересоздаёт только тестовый API. Ошибка сборки/дампа
останавливает обновление. Production, PostgreSQL и Redis не перезапускаются.
При старте новая версия создаёт недостающие таблицы приложения, поэтому дамп
нужен и при первом обновлении с 3434d2cb405a на математическое ядро 2.0.

Compose-надстройка `compose.ml-test.yml` сохраняет порт, сети, старые тома
и настройки базы из compose.test.yml; добавляет отдельный том `autoxak-test_ml`
на `/var/lib/autoxak/ml`. Dockerfile готовит этот каталог для UID 10001.
Корневая файловая система контейнера остаётся read-only. Секреты тестовой
среды не пересоздаются. APP_ENV/ML_UPLOAD_ENABLED задаются только надстройкой.

После установки управляйте этим API через постоянный скрипт, а не временную
функцию tdc и не запуском одного старого compose.test.yml:

```bash
bash /opt/autoxak-ml-source/deploy/test_ml.sh status
bash /opt/autoxak-ml-source/deploy/test_ml.sh logs
curl --fail http://127.0.0.1:8001/ready
curl --fail https://test.autoxak.ru/api/v3/ml/models
```

При последующих изменениях получите нужный коммит в checkout и выполните
test_ml.sh start. Директория исходников и Compose-надстройка должны сохраняться.
Если ранее на весь тестовый сайт был включён Nginx gate, для анонимного доступа
нужно настроить отдельные location /ml, /api/v3/ml/ и статические /static/ml.*
без этого gate. Приведённая в чате конфигурация test.autoxak.ru такого gate
не содержит. Не заменяйте виртуальный хост production.

HTTPS и Nginx остаются прежними; нужен client_max_body_size не менее 28m
(передача файлов JSON/base64) и proxy_read_timeout не менее 40 секунд.
В нашей конфигурации уже заданы 150m и 180 секунд. Браузерные запросы
проверяются на тот же origin, но это не пароль: прямой доступ API намеренно
анонимный. Для ручного клиента укажите X-Model-Manager: 1.

Хранилище включает registry.json, неизменяемые каталоги комплектов и временные
каталоги загрузки. Его необходимо резервировать отдельно от дампа PostgreSQL.
Для согласованной файловой копии остановите только тестовый API и скопируйте
том autoxak-test_ml, затем запустите API с той же Compose-надстройкой.
Не удаляйте том при обновлении. История авторов и сравнительные испытания
на поездках в эту версию функции не входят.

## Проверки

```bash
python -m pytest --confcutdir=tests/ml tests/ml
PYTHON_BIN=python node tests/browser/ml.cjs
```

Python-проверки независимы от PostgreSQL: API подключается к минимальному
FastAPI-приложению с тем же router. Проверяются реальные CBM, анонимный доступ,
отключение в production, хеши/признаки/лимиты, ошибка native validator,
активация, восстановление кэша, откат и конкурентное удаление. Браузерный тест
проверяет загрузку, применение, возврат и удаление через настоящую страницу.
