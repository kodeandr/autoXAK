# Аудит логики autoXAK — 26 октября 2026

> Исторический отчёт о предыдущей версии. Математическое ядро 2.0 и новый nullable-контракт описаны в [REFERENCE_MATH.md](REFERENCE_MATH.md).

Проверены вход и владение данными, выбор автомобиля, независимая запись GPS/IMU,
начало и завершение поездки, предварительный и итоговый расчёт, очередь
IndexedDB, история и аналитика, работа оболочки без связи и команды развёртывания.
Изменены JavaScript, серверная логика и команда начального заполнения БД.
CSS, видимая HTML-разметка, расположение элементов и изображения сохранены.
На странице истории подключён существующий модуль offline_store.js.

## Проверки

До изменений: 136 Python-тестов прошли, один опциональный интеграционный тест
staging пропущен. После изменений серверной части: **148 прошли, 1 пропущен**.
Пропущенный тест требует отдельного работающего staging и специального флага;
это не сценарий записи production-поездки.

Браузерный набор включает smoke.cjs, recording.cjs, live_metrics.cjs,
logic_audit.cjs и service_worker.cjs. Все пять наборов завершились успешно.
Первые четыре работают в Chromium
с настоящим API, PostgreSQL и IndexedDB; аппаратные события воспроизводятся
управляемыми сигналами. service_worker.cjs отдельно проверяет отказные пути
обработчика Service Worker с управляемой сетью и кэшем.

Воспроизведение на отдельной тестовой БД:

```bash
DATABASE_URL=postgresql+asyncpg://USER@HOST/TEST_DB python -m pytest -q
AUTOXAK_BASE_URL=http://127.0.0.1:8000 npm test --prefix tests/browser
```

Для сервера обязательны его обычные переменные окружения, включая SECRET_KEY.
Тесты не следует запускать на боевой БД. Дополнительно выполнены проверка
JavaScript-синтаксиса, ruff для Python, bash -n и сравнение видимой HTML/CSS
с версией до аудита.

## Границы результата

- Эти проверки не доказывают отсутствие всех возможных ошибок. Физический
  iPhone/Android, реальные Яндекс OAuth/2ГИС, длительная запись и нагрузка
  production-сервера в этой задаче не проверялись.
- Нет реальных синхронных логов смартфона/OBD. WearEngine и TwinEngine остаются
  приближёнными моделями. В частности, базовая экономия топлива использует
  допущение 1,8 л/100 км с модельной поправкой; это не измеренная экономия.
  Суммы в приложении не являются фактическим денежным балансом или выплатой.
  Исправление одинакового traffic_score может изменить новые оценки масла.
  Уже сохранённые результаты автоматически не пересчитываются.
- Для расчёта отложенных записей используются доступные серверу на момент
  обработки профиль и цены. Полного неизменяемого снимка всех расчётных
  настроек на момент начала старых записей пока нет.
- Браузер iOS может приостановить датчики в фоне. Web Locks используются при
  наличии API; на старых браузерах гарантии координации нескольких вкладок
  слабее. Сырые данные и признаки качества сохраняются.
- История без связи ограничена тем, что успело сохраниться на этом устройстве.
  localStorage — вспомогательный кэш с квотой браузера; неотправленная запись
  хранится отдельно в IndexedDB до подтверждения сервера. Очистка данных сайта
  вручную может удалить неотправленные поездки.
- Страница без ранее сохранённой оболочки требует сети. Кэш не обходит белые
  списки оператора; первый вход и серверная синхронизация требуют доступности
  домена. Сетевые настройки HOSTKEY этим аудитом не менялись.

## Развёртывание и приёмка

Изменения подготовлены в ветке feat/production-deployment. На HOSTKEY они
автоматически не установлены. Сначала установить на staging, затем на телефоне:

1. Войти, выбрать автомобиль, повторно открыть гараж и сверить выбор.
2. Проверить разрешения и импульсы в разных положениях телефона на месте;
   километры и деньги от этого не должны появляться.
3. Выполнить короткую реальную поездку с телефоном в держателе и открытым экраном,
   завершить её, сверить результат и историю.
4. Записать отдельную поездку без сети, проверить её наличие в истории,
   восстановить связь и убедиться в одной серверной записи и одном начислении.
5. Ввести показание БК, проверить повторное открытие и экспорт.

Для существующего checkout production, который уже отслеживает эту ветку:

```bash
cd /opt/autoxak-production
bash deploy/production.sh update
bash deploy/production.sh check
```

update делает резервную копию, подтягивает текущую отслеживаемую ветку,
строит образ и заменяет API. Старую миграцию и ротацию ключей повторять не нужно.
Схема БД для изменений этого аудита не требует новых столбцов или удаления данных.
