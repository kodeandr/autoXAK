Проверены серверный код, аутентификация, PostgreSQL, обработка телеметрии,

## Результаты проверок

- **70 Python-тестов прошли**, без пропусков, ошибок и падений. Тесты включают
  PostgreSQL-конкуренцию, целостность повторных отправок и перенос аккаунтов,
  потоковый экспорт v2 с модельным расчётом, совместимость со старой схемой.
- Браузерные регрессии в **системном Chromium через Playwright** прошли: вход,
  гараж, история, сохранение настроек и износа, service worker, офлайн-очереди,
  отказ сервера, прерывание IndexedDB, восстановление записи и очистка GPS watcher.
  События датчиков в этих тестах синтетические; аппаратная проверка не выполнялась.
- Функциональная проверка API: каталог 9 модификаций, запись/дедупликация/завершение
  поездки, положительная оценка CatBoost с проверкой артефактов, экспорт 61 GPS-точки,
  сохранение legacy-телеметрии, dashboard и Redis SET/GET/DELETE.
- HTTPS-запуск проверен с проверкой сертификата и явным доверенным CA.
- `pip-audit -r requirements.txt`: известных уязвимостей не обнаружено.
  `npm audit` для браузерных тестов: 0 известных уязвимостей.
- `ruff check app --select F`, проверка совместимости Python-пакетов и
  `docker compose config --quiet` прошли.
- Добавлен GitHub Actions workflow. Его команды проверены локально; выполнение
  самого workflow на GitHub ещё не проверено.
- CSS, HTML-разметка и ресурсы четырёх экранов не менялись. Сравнение с исходной
  версией вне содержимого `<script>` подтвердило идентичность разметки и стилей.

Команды воспроизведения описаны в README. Новые регрессионные тесты находятся в
`tests/test_audit_regressions.py` и `tests/browser/smoke.cjs`.

## Что остаётся открытым

**Точность WearEngine не подтверждена и не исправлена калибровкой.**
Синтетические штатные проверки показали расхождение с OBD-формулой:

| Проверка | Расхождение |
| --- | ---: |
| Skoda Octavia 1.4 | 50,01% |
| Skoda Octavia 2.0 | 54,31% |
| Haval Jolion | 55,83% |
| Отдельный синтетический цикл `run_verification.py` | 58,61% |

Это сравнение двух расчётных моделей на синтетических сигналах, а не измеренная
дорожная точность. Текущая реализация WearEngine не воспроизводит весь заявленный
в README физико-химический аппарат. Пользователь подтвердил, что реальных парных
логов сейчас нет. Подгонка коэффициентов под эти примеры не устранит проблему.
Нужны реальные синхронизированные записи, согласованное определение эталонной
наработки и независимые контрольные поездки. До этого нельзя гарантировать
MAPE ≤10% или называть расчёты эталонными. README дополнен этим ограничением.

**Опубликованные секреты необходимо отозвать и заменить.** Удаление ключей из
текущих файлов не удаляет их из Git-истории и не отменяет действующие значения.
Ротация 2ГИС/Яндекс, пароля развёрнутой БД и TLS-ключа требует действий в реальной
среде. Не выполнялись вход в провайдеров, изменение сервера или публикация.

Реальные Яндекс OAuth/2ГИС, аппаратные датчики iOS/Android, длительная нагрузка,
отказоустойчивость боевой инфраструктуры и восстановление новой облачной задачи
не проверены. Аудит и успешные регрессии не являются доказательством отсутствия
всех возможных дефектов вне проверенных сценариев.
