# Обзор функций autoXAK: 25 секунд

Готовый ролик — `sample-video-app-tour-25s.mp4`. Синтетические данные обозначены на видео. Все экраны и показатели получены от обычного приложения; монтаж сокращает ожидания и середину поездки, а не меняет расчёты.

## Что показано

Вход `demouser` с посимвольным вводом логина и скрытого пароля; просмотр истории и 30-дневного графика; выбор автомобиля в гараже; старт и сразу движущаяся дистанция; окончание поездки 13,02 км; полный свайп; итоги; нажатие копилки; обновлённая главная; 7-дневный график и прокрутка последних поездок. Ожидание HTTP-расчёта и первые неподвижные секунды вырезаны монтажом; скорость приложения этим не изменена. Между сценами — короткие плавные переходы.

## Данные готового примера

- 59 предыдущих поездок: по 20 минут, каждая 10–15 км; всего 716,09 км и 1 775,48 ₽.
- Новая поездка: 13,02 км, 20 минут, 50,72 ₽; итоговый баланс 1 826,20 ₽, 60 поездок.
- Каждая поездка обработана штатным `POST /api/v1/telemetry/session`, с 60 001 IMU-отсчётом и 1 201 точкой GPS.
- Индексы, средние, дельты и баланс вычисляет backend. Числа графика, рубли и ответы API не подменяются. Контрольные суммы и результаты конкретного примера доступны в JSON-отчётах архива.
- Модельная экономия синтетического сценария не подтверждает дорожную точность или эффект на реальном водителе.

## Подготовка локальной демонстрационной копии

Нужны Node.js 22 или новее, работающая обычная версия autoXAK с исправлениями продуктовых эпиков, PostgreSQL/Redis и каталог с `haval_jolion_15t_4wd`. На ML-ветке `93a61f6ffcb9` интерфейс поездки другой; для этого демо она не подходит.

Скачайте Node.js с https://nodejs.org. Для монтажа нужен FFmpeg с libx264 и drawtext. В Windows можно установить его командой:

```powershell
winget install --id Gyan.FFmpeg -e
```

После установки откройте новый PowerShell. Распакуйте архив в отдельную папку; код приложения заменять не нужно.

В папке `autoxak-demo` подготовьте историю:

```powershell
node .\prepare-progress.cjs --url "http://localhost:8000"
```

Команда допускает только loopback-адрес и предназначена для отдельной локальной демо-базы. Она регистрирует нового пользователя `demouser`, задаёт автомобиль/городской расход через API и сохраняет 59 полных синтетических поездок. Подготовка занимает несколько минут и сохраняет несколько миллионов точек; не запускайте её на production или на туннеле в production.

Создаётся `demo-account.private.json` с логином и паролем: сохраняйте его приватным. В архив он не включён. `history-preparation-report.json` содержит результаты поездок без пароля/токена. Подготовка останавливается, если приватный файл уже существует. Для другого нового пользователя предусмотрено `--login AnotherDemo` (5–15 латинских букв). Логин `demo` не используется, поскольку текущая валидация требует минимум 5 букв.

## Windows: запись и монтаж одной командой

После подготовки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Record-Demo.ps1 -Url "http://localhost:8000" -Tour
```

Обёртка устанавливает закреплённый Playwright и Chromium, записывает браузер и запускает FFmpeg. Не закрывайте окно во время записи. `-Headless` позволяет работать без видимого окна; `-AccountFile` выбирает другой приватный файл. Адрес должен совпадать с адресом подготовки.

Результаты находятся в `output/<время>/`:

- `demo-app-tour-25s.mp4` — итоговый ролик без звука;
- `demo.webm` — исходная запись;
- `report.json` — реальные результаты API и проверки UI;
- `tour-edit-report.json` — монтажные участки и темп;
- `telemetry.synthetic.json` — полный экспорт новой поездки;
- снимки итогов и графиков.

## Linux / macOS

```bash
npm ci
npx playwright install chromium
node prepare-progress.cjs --url http://localhost:8000
node record-demo.cjs --url http://localhost:8000 --headless --tour
```

В Linux могут потребоваться системные зависимости Chromium. Для установленного Chromium поддерживается `CHROMIUM_PATH`. Для другого шрифта с кириллицей задайте `DEMO_FONT_PATH` (Windows по умолчанию Segoe UI, Linux DejaVu Sans).

## Повторный монтаж

Исходная папка новой записи должна содержать `demo.webm` и `report.json` с полными маркерами сцен:

```powershell
node .\edit-tour.cjs .\output\ПАПКА_ЗАПИСИ
```

Дополнительные режимы записи сохранены: без флагов — новая гостевая минутная поездка; `-Short` — 20-секундное демо без прежней истории; `-Progress` — базовая запись со входом и графиками. Для последнего нужен подготовленный аккаунт. Для текущей редакции используйте `-Tour`; прежний `-Dynamic` также сохранён.

## Проверка и ограничения

Сценарий проверен в Chromium на Linux с настоящими PostgreSQL/Redis и отдельной базой. Проверены все 59 исторических расчётов, сохранение новой поездки, прибавление её суммы ровно один раз, перезагрузка истории, средние и графики 7/30 дней. Итоговое видео H.264, 414×896, 30 кадров/с, ровно 25 секунд. Windows-обёртка в этой среде не исполнялась.

Подготовка и запись создают демонстрационные записи, существующие аккаунты не используются. Их автоматического удаления нет. Ошибки записи сохраняются в отчёте и не маскируются под успешное демо. Код математического ядра, дизайн и правила авторизации приложения инструмент не меняет.


## Вариативная телеметрия (сохранена)

Вариативные входы поездки и исторических дней сохранены из предыдущей редакции. Обзор добавляет историю и гараж, не меняя математические формулы.

Новая городская траектория содержит плавные и интенсивные изменения скорости, остановки, медленную очередь и семь вертикальных импульсов во время движения. При штатной обработке получены: 3 резких разгона, 4 торможения, 7 неровностей, индекс 97/100; время ниже порога скорости около 223 секунд (интерфейс округляет до 4 минут). Это модельный показатель низкой скорости, а не измеренный диагноз пробки.

Для 59 исторических дней длительность эпизодов динамического стресса и базовая скорость получают небольшие воспроизводимые вариации из фиксированного seed. Дневные индексы могут как улучшаться, так и ухудшаться. Никакие конечные индексы, дельты, рубли, графики или счётчики вручную не задаются: история сохраняется штатным API, график строится по его ответам. Воспроизводимые синтетические колебания не являются статистикой реальных водителей.


## Обзор функций: текущий монтаж

Режим `-Tour` сохраняет вход demouser с посимвольным паролем и добавляет в начало реальное посещение истории (переключение периода и прокрутка поездок), затем гаража. В гараже показываются марка, модель, модификация и сохранение автомобиля. После нажатия старта коротко виден начальный HUD, затем монтаж переходит к участку, где реальный счётчик дистанции уже растёт. Первые неподвижные секунды вырезаны из видео; полный массив исходной поездки сохранён.

Из конца удалён долгий статичный показ 30-дневного графика: этот период показан при первом посещении истории. В конце остаются обновлённый 7-дневный график и прокрутка к сохранённым поездкам. Итоги, свайп, копилка, синтетические данные и правила расчёта сохраняются. Длительность — 25 секунд.

Для повторного монтажа записи с новыми маркерами:

```powershell
node .\edit-tour.cjs .\output\ПАПКА_ЗАПИСИ
```

Результат — `demo-app-tour-25s.mp4` и `tour-edit-report.json`. Проверки включают фактический накопленный пробег больше 5 метров в начале выбранного движущегося участка. Значения счётчиков не редактируются.
