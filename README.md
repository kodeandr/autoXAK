# АвтоХАК — запись поездок и ML-оценка расхода бензина

Приложение записывает GPS, акселерометр и гироскоп смартфона, сохраняет исходные данные
на телефоне и сервере, затем оценивает расход бензина обученной гибридной моделью:
**физическая основа + поправка CatBoost**. Модель работает локально на сервере.
Точность на реальных смартфонах и пилотных Audi пока не подтверждена.

## Возможности этой версии

- Полная запись поездки отдельными событиями GPS и датчиков; времена измерений в миллисекундах.
- Порционное сохранение в IndexedDB во время записи, повторная доставка при восстановлении связи.
- Повторы отправки не создают новые поездки и не увеличивают число точек.
- Профиль конкретной машины фиксируется в поездке: топливо, масса, объём, турбина и описательные поля.
- После «Окончить» измерения прекращаются, накопленные данные сохраняются и досылаются.
- Гибридный расход на пригодных интервалах, доля покрытия и причины отсутствия оценки.
- Необязательные контрольные показания бортового компьютера за тот же интервал.
- История и выгрузка исходной поездки; доступ к серверной записи только её владельцу.

**Модель предсказывает литры бензина, а не сэкономленные литры.** Прямой CatBoost и физическая
основа сохраняются как альтернативные расчёты для исследования. Их разность не является экономией.
Двигатель предполагается работающим от старта до завершения, включая остановки.
При потере GPS расход пропуска не выдумывается; отсутствие данных не превращается в нулевую скорость.

Генератор виртуальной поездки ещё не включён. Прежние положительные начисления по фиксированному
коэффициенту и расчёт масла отключены от активного API и интерфейса. Старые таблицы остаются в БД,
но их суммы не смешиваются с новыми результатами. Старый README сохранён в `docs/legacy/README-v1.md`.

## Локальный запуск

Нужен Python 3.12. Из корня репозитория:

```sh
python -m venv .venv
# Активировать окружение (Windows PowerShell): .venv/Scripts/Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть `http://127.0.0.1:8000`. По умолчанию используется локальная SQLite `autoxak.db`;
при старте создаются недостающие таблицы. PostgreSQL подключается через `DATABASE_URL`
в формате `postgresql+asyncpg://...`. Для рабочей БД используйте резервную копию перед обновлением.
Новые записи находятся в отдельных таблицах; изменения существующих колонок и удаление поездок не выполняются.

Для устойчивого входа после перезапуска задайте **один постоянный случайный SECRET_KEY** минимум 32 символа
в окружении сервера. В локальном режиме без него генерируется ключ на один процесс;
в производственном режиме (`AUTOXAK_ENV=production`) отсутствие ключа запрещает запуск.
Несколько процессов должны использовать один ключ. Файлы `.env` не коммитятся.

На телефоне нужен доступ к сайту по доверенному HTTPS. Для проверки удерживайте приложение открытым
и закрепите телефон: браузер может приостанавливать GPS/датчики при блокировке или сворачивании.
Такие интервалы видны как пропуски, приложение не обещает фоновую запись.

Для входа через Яндекс задать `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` и
`YANDEX_REDIRECT_URI` в окружении и зарегистрировать тот же callback в Яндекс ID.
Callback: `https://ваш-домен/api/v1/auth/yandex/callback`; HTTP допускается только на localhost.
Постоянный `SECRET_KEY` должен совпадать между процессами и перезапусками;
при обновлении сохраняйте прежний ключ, если уже есть аккаунты Яндекса.
Ключи из прежней истории Git необходимо перевыпустить и хранить только в окружении.
Без настройки Яндекс-вход недоступен; запись в гостевом профиле работает.
Вход в другой аккаунт не переносит поездки автоматически: сначала завершить и
отправить записи, старые локальные данные остаются доступными для резервной выгрузки.

## Docker

Скопировать `.env.example` в `.env`, задать случайный `SECRET_KEY`, затем:

```sh
docker compose up --build
```

API слушает порт 8000 по HTTP за вашим HTTPS-прокси. Ранее закоммиченные локальные сертификаты
и ключи не используются новым контейнером. `DGIS_API_KEY` пока не нужен для расчёта расхода;
интеграция дорожного контекста — следующий этап. Параметры БД dev-compose предназначены для локальной проверки.

## Проверка

```sh
python -m pytest
node --test tests/frontend/*.test.cjs
```

Python-тесты проверяют API, изоляцию владельцев, повторы и конкурентные отправки, экспорт всех точек,
границы времени, пропуски и сохранённые модели. JS-тесты проверяют запись и повторы синхронизации.
Исторические тесты старых исследовательских модулей также сохранены, но не являются проверкой точности двойника.

Дополнительная проверка в настоящем браузере: установить Playwright с браузером Edge,
запустить отдельный локальный сервер на порту 8765 и выполнить
`node tests/frontend/browser_smoke.cjs`. Сервер должен использовать тестовую БД.
`AUTOXAK_BASE_URL` задаёт другой адрес, `BROWSER_CHANNEL` — браузер, `PLAYWRIGHT_MODULE` — путь к пакету.
Тест использует отдельный профиль браузера, синтетические датчики и реальную модель;
проверяет офлайн-запись, полную выгрузку, остановку, восстановление и конкурентное завершение.
Настоящий вход на Яндекс и установка Docker в эти локальные проверки не входят.

Перед пилотом на каждом телефоне проверить разрешения датчиков, закрепление, обычный разгон,
остановку, поворот, потерю сети, завершение и выгрузку. Сверить GPS-время и время кнопок.
При переходе со старой гостевой сессии сначала выгрузить локальные записи; восстановление сессии
не должно автоматически приписывать старые поездки новому аккаунту.

- OpenAPI: `/docs`. Основные маршруты: `/api/v2/vehicle`, `/api/v2/trips` и блоки/завершение/экспорт поездки.

Старые `/api/v1/telemetry/session`, `/api/v1/trips/complete`, `/api/v1/analytics/verify-run`
и старые пользовательские сводки возвращают 410 с указанием нового API. Это явный переход формата;
старый клиент не должен молча продолжать начислять эвристическую экономию.

## Следующие этапы цифрового двойника

1. Собрать контрольные поездки на трёх машинах и проверить перенос с автомобильной скорости VED на GPS.
2. Привязать реальный трек к дороге через выбранный API 2ГИС: маршрут, ограничения, повороты и доступные остановки.
   Наличие светофора не сообщает текущую фазу сигнала.
3. Построить виртуальное движение той же машины на той же дистанции: более резкие, но допустимые
   разгоны и торможения; одинаковые условно заданные задержки на остановках.
4. Пересчитать признаки виртуальной траектории и пропустить обе поездки через одну версию модели.
5. Оценить разницу «виртуальный расход минус фактический прогноз», сохраняя нулевые и отрицательные значения,
   и показывать экономию только с учётом неопределённости. Проверка расхода и проверка сценария — отдельные задачи.
