## 🚀 О проекте и назначение

Классические телематические системы мониторинга автопарка требуют установки дорогостоящих трекеров или диагностических сканеров в порт OBD-II. «АвтоХАК» решает задачу безаппаратно: источником данных выступают стандартные сенсоры смартфона водителя (**DeviceMotionEvent** на частоте 50 Гц и геолокация GPS 1 Гц).

### Ключевые возможности:
- **Безаппаратный сбор:** непрерывная фиксация кинематики на частоте 50 Гц через браузерный PWA-клиент с удержанием экрана (`Screen Wake Lock API`).
- **Офлайн-автономия:** буферизация пакетов телеметрии в `IndexedDB` при пропадании связи с последующей идемпотентной отправкой по контрольным суммам SHA-256.
- **Очистка от дорожных артефактов:** аппаратная развязка продольного разгона и вертикальных толчков от ям/кочек алгоритмом `Z-Shock Veto`.
- **Контрфактический цифровой двойник:** математический расчет потенциальной экономии ($\Delta C$, ₽) относительно нормативного скоростного потока (2GIS API Platform) и стиля «агрессивного двойника».
- **Двухконтурное версионирование API:** строгое разделение детерминированного физического Baseline (`/api/v1/`) и надстройки машинного обучения CatBoost (`/api/v2/`).

## 🏗 Архитектура системы и конвейер данных

Система построена по принципу модульного монолита на базе **FastAPI**, развернутого в Docker-контейнерах за обратным прокси-сервером **Nginx** с SSL-терминацией.

```text
[ Смартфон (PWA / JS) ]
   │
   │  • DeviceMotionEvent (IMU 50 Гц: ax, ay, az, gx, gy, gz)
   │  • Geolocation API (GPS 1 Гц: lat, lon, speed, accuracy)
   │  • Буфер IndexedDB (пакетирование чанков по 60 с)
   │
   ▼ HTTPS / JSON (Чанки с SHA-256)
[ Обратный прокси: Nginx (SSL / Port 443) ]
   │
   ▼ Асинхронный сокет (Port 8000)
[ Серверное ядро: FastAPI (Python 3.11 / Uvicorn) ]
   │
   ├── 1. Модуль DSP (app/core/dsp/filters.py):
   │      ├─ Матричная автоориентация SO(3) по ISO 8855
   │      ├─ Двунаправленный ФНЧ Баттерворта 4-го порядка (fc = 2.5 Гц)
   │      └─ Фильтр аномалий покрытия Z-Shock Veto (|az| > 4.2 м/с², окно 0.7 с)
   │
   ├── 2. База данных автопарка (PostgreSQL 16 / asyncpg):
   │      └─ Нормализованный каталог VehicleTrim (масса, Cd*A, КПД коробки)
   │
   ├── 3. Внешний гео-контекст (Redis + 2GIS API Platform):
   │      ├─ Сжатие трека алгоритмом RDP на 82.4% (filters.py)
   │      └─ Кэширование дорожных сегментов и скоростных лимитов в Redis
   │
   ├── 4. Физическое ядро TwinEngine (/api/v1/):
   │      ├─ Квазистатический тяговый баланс P_тяга(t) и работа E+
   │      └─ Расчет дельты экономии: ΔC = p * (V_двойник - V_факт)
   │
   └── 5. Модуль ML-коррекции (/api/v2/trips):
          └─ Инференс CatBoost по 13 агрегированным признакам (устранение невязки)
```

**Быстродействие:** полный цикл фильтрации и расчета 60-секундного чанка (3 000 точек) занимает **14–18 мс** при допустимом регламенте SLA $< 50$ мс.

## 🔬 Физико-математическое ядро (TwinEngine)

Расчетное ядро (`app/services/twin_engine.py`) опирается на принципы квазистатического тягового баланса (стандарты *SAE J1979*, модели *CMEM* и *VT-Micro*).

1. **Мгновенная тяговая сила и мощность:**
   $$F_{\text{тяга}}(t) = m \cdot a_x(t) + m g f_{\text{кач}} + \frac{1}{2} \rho C_d A v(t)^2 + m g \sin\theta$$
   $$P_{\text{тяга}}(t) = \max\left(0, \frac{F_{\text{тяга}}(t) \cdot v(t)}{\eta_{\text{транс}}}\right)$$

2. **Двухпараметрическая модель расхода топлива:**
   $$V_{\text{расч}} = \theta_E \cdot E_+ + \theta_T \cdot T$$
   - $E_+ = \int P_{\text{тяга}}(t) \, dt$ — полезная положительная механическая работа на колесах (МДж);
   - $T$ — общее время движения с учетом холостого хода (ч);
   - $\theta_E = 0{,}1239\text{ л/МДж}$ — топливный эквивалент механической энергии;
   - $\theta_T = 1{,}5140\text{ л/ч}$ — базовая часовая нагрузка холостого хода и бортовых систем ДВС.

3. **Контрфактический двойник:**
   $$\Delta C = p \cdot \max(0, V_{\text{двойник}} - V_{\text{факт}})$$
   Модель симулирует движение «агрессивного двойника» на том же треке со скоростными лимитами 2ГИС, изолируя манеру работы с педалью газа от внешних пробок.

4. **Трибологический модуль (WearEngine):**
   Оценивает термическое окисление моторного масла по кинетике Аррениуса ($E_a = 106{,}17\text{ кДж/моль}$) и механический срыв пленок ZDDP. В городском цикле экономия ресурса масла составляет $\approx 1{,}40\text{ ₽}$ за поездку против $25\text{--}50\text{ ₽}$ на топливе (соотношение 1 : 30), в связи с чем показатель перенесен в R&D-контур и B2B-телематику.

## 📡 Цифровая обработка сигналов (DSP-конвейер)

Реализована в модуле `app/core/dsp/filters.py`:

- **Автокалибровка положения $SO(3)$:** ортогональная матрица поворота приводит произвольно ориентированный смартфон в базис кузова автомобиля (ISO 8855) по вектору гравитации и кинематическому ускорению первых секунд движения.
- **Фильтрация вибраций:** двунаправленный фильтр Баттерворта 4-го порядка (`scipy.signal.filtfilt`, $f_c = 2{,}5\text{ Гц}$) исключает фазовый сдвиг и подавляет высокочастотный шум двигателя.
- **Алгоритм Z-Shock Veto:** при обнаружении вертикального импульса подвески ($|a_z| > 4{,}2\text{ м/с}^2$) на скорости $v \ge 7{,}2\text{ км/ч}$ накладывается рефрактерная маска длительностью $0{,}7\text{ с}$, блокирующая ложные штрафы за резкое замедление на ямах и лежачих полицейских.
- **Сжатие маршрута (RDP):** алгоритм Рамера — Дугласа — Пекера сжимает GPS-трек на $80\text{--}85\%$ без искажения геометрии маневров для оптимизации кэша Redis.

## 🚀 Быстрый старт и локальное развертывание

### 1. Системные требования
- Docker Engine 24.0+ и Docker Compose V2;
- Смартфон с современным браузером (Safari iOS 14.5+ или Chrome Android 90+) с поддержкой Generic Sensor API.
- *Примечание:* доступ к гироскопу и акселерометру в мобильных браузерах аппаратно разрешен **только по защищенному протоколу HTTPS**.

### 2. Клонирование репозитория
```bash
git clone https://github.com/kodeandr/autoXAK.git
cd autoXAK
```

### 3. Конфигурация переменных окружения (`.env`)
Создайте файл `.env` в корневой директории:
```ini
# Генерация ключа: python -c "import secrets; print(secrets.token_hex(32))"
SECRET_KEY=your_persistent_secret_key_at_least_32_chars
DATABASE_URL=postgresql+asyncpg://autoxak_user:autoxak_pass@postgres:5432/autoxak_db
POSTGRES_USER=autoxak_user
POSTGRES_PASSWORD=autoxak_pass
POSTGRES_DB=autoxak_db
REDIS_HOST=redis
REDIS_PORT=6379
DGIS_USE_MOCK=true
DGIS_API_KEY=your_2gis_api_platform_token
```

### 4. Генерация локальных SSL-сертификатов
```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout key.pem -out cert.pem \
  -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
```

### 5. Запуск комплекса в Docker Compose
```bash
docker compose up --build -d
```
Убедитесь, что все контейнеры работают штатно:
```bash
docker compose ps
```

### 6. Первичная инициализация базы данных
```bash
# Наполнение каталога автомобилей нормативными характеристиками
docker compose exec api python seed_fleet.py

# Наполнение матрицы региональных цен на топливо
docker compose exec api python seed_fuel_prices.py
```

### 7. Проверка доступности сервиса
```bash
curl --insecure https://localhost:8000/health
```
Ожидаемый ответ:
```json
{
  "status": "ok",
  "service": "autoXAK Dynamic Twin Engine",
  "version": "2.0.0",
  "database": "connected"
}
```

## 🔒 Конфиденциальность и безопасность (152-ФЗ)

Сервис «АвтоХАК» спроектирован по стандарту **Privacy by Design**:
1. **Отсутствие сбора персональных данных:** аутентификация в приложении происходит через генерацию случайного `guest_uuid`. В схеме БД отсутствуют поля для хранения ФИО, телефонных номеров, адресов почты, государственных регистрационных знаков и VIN-кодов автомобилей.
2. **Пространственная обфускация координат:** первые и последние 300 метров маршрута не сохраняются в виде точных географических точек, предотвращая деанонимизацию мест проживания и работы пользователя.
3. **Безопасность сессий:** обмен данными шифруется по протоколу TLS 1.3, сессии авторизуются через асимметричные токены JWT.
